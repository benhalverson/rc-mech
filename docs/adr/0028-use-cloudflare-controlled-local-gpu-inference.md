# Use Cloudflare-controlled local GPU inference

**Status:** accepted

Cloudflare remains the sole control plane for Driving-analysis lifecycle, queue semantics, authorization, and durable state, while the first production Tracking provider runs SAM 3.1 on the Owner's local RTX 3090 behind Cloudflare Tunnel and Access. The local service is a stateless, recoverable execution worker with one active leased job: Cloudflare acquires the lease before minting narrowly scoped R2 transfer capabilities and making an idempotent submission, releases it when a Tracking gap requires User Re-identification, and reconstructs later work from Cloudflare state and immutable R2 artifacts after an outage. This supersedes ADR 0025 because Cloudflare Containers expose CPU, memory, and disk but no GPU resource; the Python container remains responsible for Cloudflare-side media orchestration while model execution moves behind the versioned Tracking-provider boundary.

The local worker receives no R2 credentials or application authority. It is reached only through a private hostname protected by Cloudflare Access service authentication, downloads the authorized source through a short-lived object-specific GET Transfer grant, and publishes compact Subject-observation artifacts through a short-lived object-specific PUT Transfer grant. Transfer grants are renewable execution-attempt capabilities: their URLs are never persisted, logged, included in provenance, or hashed into idempotency inputs, and renewal preserves the segment ID and specification digest. Only Cloudflare holds the signing credentials and accepts an uploaded artifact after validating its checksum, size, contract, and segment binding.

Input GET and output PUT grants use one pull-compatible handshake. The local status reports `transfer-grant-required` with the segment, attempt, transfer role, and a stable transfer-request ID, but no URL. After validating the active lease and fencing token, Cloudflare delivers the ephemeral grant through a separate idempotent command. The worker holds the URL only in memory, redacts it from logs, uses it for that transfer, and discards it. Grant expiry or transfer retry reuses the same transfer-request ID and logical transfer, so reissuance changes neither segment, attempt, immutable specification, nor provenance.

Each local job executes exactly one immutable Tracking segment; infrastructure retries reuse its segment ID, while Re-identification creates a new segment under the same immutable run. Local execution state and caches may be mutable and recoverable, but Cloudflare never treats local queue, scratch state, cached media, or cached model state as authoritative, and no GPU lease remains held while waiting for a User correction.

One `DrivingAnalysisWorkflow` instance owns orchestration for one immutable run. Segment and execution-attempt activity is subordinate to that run-level Workflow: it prepares media once, drives each Tracking segment, waits durably for Re-identification without holding the GPU, and then coordinates measurement, clip rendering, and finalization. Every wake, retry, and replay reloads authoritative D1 state rather than trusting Workflow memory. A retry that creates a new run, including selection of another provider or profile, also creates a new Workflow instance.

The local service never waits for User input. A Tracking gap terminates its segment successfully with `status=completed` and `outcome=tracking-gap`; the immutable result contains observations through the last trusted point and the gap descriptor. Only after validating that artifact does Cloudflare release the GPU lease and transition the authoritative Driving analysis to `awaiting-reidentification`. The local service does not expose that User-facing lifecycle state.

One singleton `GpuLeaseCoordinator` Durable Object serializes access to the one physical GPU. It persists only ordered waiters, one active lease, a unique lease ID, and a monotonically increasing fencing token; D1 remains authoritative for Driving-analysis lifecycle and accepted evidence, and Workflows remain the orchestrator. Acquire, renew, release, cancellation, progress, and artifact acceptance are conditioned on the active lease ID and fencing token so a stale execution cannot mutate authoritative state after expiry or reassignment. A successful lease is released only after Cloudflare validates and commits the segment artifact; cancellation, expiry, or failure may release it earlier. The coordinator never stores analysis lifecycle or evidence.

Version-one waiter ordering is persisted FIFO using a monotonically increasing coordinator ordinal. A Re-identification segment joins the tail when it becomes ready, like any other segment. Infrastructure retries reuse the segment's existing waiter and queue position, stale-physical-capacity recovery retains the head position, and cancellation removes the waiter. Once physical GPU processing begins, execution is non-preemptive until the segment reaches one of its defined termination conditions.

Because D1 and the Durable Object do not share a transaction, lease activation is deliberately fail-closed. Cloudflare first acquires a coordinator lease, then conditionally creates or activates the execution attempt in D1 with that lease ID and fencing token, and only after that D1 transaction commits may it issue Transfer grants or contact the GPU. If D1 activation fails, Cloudflare releases the unused lease or allows it to expire without external execution side effects. Recovery, renewal, submission, cancellation, progress handling, and artifact acceptance proceed only while D1 and the coordinator agree on the active lease and fencing identity; a mismatch is fenced rather than repaired by assumption.

The initial GPU-control protocol is Cloudflare-initiated and pull-only. A provider-neutral `TrackingProvider` interface lives at the trusted TypeScript control-plane boundary, and its initial `LocalSam31Provider` calls the fixed, Access-protected GPU hostname directly from Worker code. Cloudflare submits and cancels executions and polls status; every response binds to the expected segment, attempt, lease, fencing, and Inference-profile identities, and only a valid current response permits lease renewal. Access credentials, lease and fencing validation, retries, Transfer-grant issuance, and provider selection stay in the trusted Worker. The local service has no application or control-plane credential and cannot renew its own authority. It separately enforces one physical GPU execution at a time because lease expiry fences stale results but does not terminate computation. Future callbacks may reduce polling latency but are never required for correctness.

`LocalSam31Provider` is fixed-origin egress. Its HTTPS-only GPU origin is supplied by deployment configuration and normalized once at startup; browser input, API requests, D1 values, and provider payloads can influence neither scheme, host, nor port. Provider operations construct only allowed relative paths, inject Access credentials only after the resolved origin exactly matches the configured origin, reject redirects, and apply strict request timeouts and response-size limits before Zod parsing. Absolute input URLs, alternate schemes or ports, origin mismatches, redirects, and malformed or oversized responses fail closed without forwarding credentials.

Artifact publication is a two-phase, attempt-specific protocol. After finalizing an artifact locally, the worker enters `output-ready` and reports only its checksum, byte count, contract version, and current segment, attempt, specification, Inference-profile, lease, and fencing identities. Cloudflare issues a short-lived PUT Transfer grant to an attempt-specific staging key only while that execution remains authoritative. After upload, Cloudflare independently validates the staged checksum, byte count, contract, successful outcome, segment and attempt binding, specification and profile digests, lease ID, and fencing token, then promotes the exact bytes to a separate accepted-evidence key that is never exposed through a PUT Transfer grant. After validating the promoted object, Cloudflare acquires a bounded coordinator commit hold conditioned on the same lease and fencing token so that authority cannot expire or be reassigned during the final conditional D1 commit. The coordinator stores only this temporary lease state, never the artifact or evidence decision. Cloudflare atomically binds the accepted key and checksum in D1 and then releases the lease. D1 never references staging as evidence; expired, cancelled, and stale executions receive no new grant, and staging objects are disposable garbage-collection candidates even if a still-live presigned capability rewrites them.

Only the successful segment outcomes `race-window-complete` and `tracking-gap` can produce accepted Tracking observations. Cancelled, interrupted, stale, and provider-failed attempts may retain bounded diagnostic metadata, but their partial observations and staging objects never become accepted evidence. A retryable execution failure creates another attempt under the same immutable segment and specification; a deterministic terminal provider failure ends the run with a stable failure code rather than publishing partial Tracking evidence.

The GPU provider receives only the immutable prepared Race-window Track-view artifact and its frame manifest, never a Transfer grant for the original Race recording. The stateless Cloudflare Python container retains only stages that require its media runtime: probing, preparation, and Corner-clip rendering. It validates the source, extracts the selected Race window, crops the fixed Track view, preserves source timestamp and frame-index provenance, and publishes checksum-bound prepared media to private R2. Every Tracking segment in a run references that same descriptor, and any local checksum-keyed copy is a disposable cache.

The local FastAPI service retains strict Pydantic contracts and the reusable provider-neutral Subject-observation and Tracking contracts; shared accepted and rejected fixtures preserve Zod-to-Pydantic parity at the TypeScript boundary. Cloudflare Access and Tunnel remain the public trust boundary, while local FastAPI listens only on `127.0.0.1:8080` for same-host `cloudflared` traffic.

Every run pins one immutable Inference profile covering provider, model version and digest, pipeline version and digest, runtime image digest, preprocessing, precision, confidence calibration, thresholds, tracking configuration, and prompt semantics. A versioned canonicalization scheme produces its digest so later serialization changes cannot silently alter the identity of an existing profile. Every Tracking segment in the run uses that profile; Re-identification changes only the next segment's seed. Lease IDs, fencing tokens, execution-attempt IDs, Transfer grants, hostnames, timestamps, wall-clock performance, resource measurements, hardware identity, and driver observations remain attempt metadata outside the profile digest.

Profile matching fails closed across the full execution chain: `run.inferenceProfileDigest`, `submission.profileDigest`, `worker.resolvedProfileDigest`, and `artifact.profileDigest` must be identical. The local worker accepts a submission only when its installed model, pipeline, runtime, precision, and other inference-affecting configuration resolve to the requested digest, and every status response and artifact repeats that digest for Cloudflare validation. Provider unavailability or an incompatible worker upgrade may make an existing run wait, retry, fail retryably, or be cancelled under its original deadline, but it never changes the run's profile. Selecting another provider or profile creates a new run that regenerates Tracking evidence from immutable source inputs rather than consuming observations from the previous run.

The authenticated public contract exposes stable provenance: run ID, Inference-profile digest, Tracking-segment ID and order, successful segment outcome, gap descriptors, and accepted-artifact digest. Execution authority and infrastructure mechanics remain internal, including attempt IDs, lease IDs, fencing tokens, transfer-request IDs, staging keys, Access details, GPU hostname, and machine identifiers. Public failures use stable safe codes rather than provider responses or infrastructure identities.

Local execution states such as downloading, processing, output readiness, transfer activity, retry, recovery, and lease waiting remain internal. Cloudflare projects them onto the existing public analysis statuses and stages, exposes at most a coarse safe wait reason rather than an exact FIFO position, and does not create public states for execution mechanics. Public progress is a monotonic high-water mark within one run, so an attempt restart cannot move it backward; pre-completion progress is capped at 99 percent, and only the authoritative final commit publishes 100 percent. `awaiting-reidentification` is published only after a `tracking-gap` artifact has been validated, promoted, and accepted.

Version one gives each ready Tracking segment a configurable 24-hour provider-availability deadline beginning when the segment first becomes executable; retries never extend it. Before the first segment begins, the analysis remains `queued` with a safe `waiting-for-provider` or `waiting-for-capacity` reason. After any Tracking evidence has been accepted, the analysis never regresses to `queued`; a later wait remains `running` at the `tracking` stage with the same safe reason. Capacity contention uses the `GpuLeaseCoordinator` waiter mechanism, while provider or Tunnel unavailability uses bounded exponential backoff. Deadline expiry fails the run retryably with `TRACKING_PROVIDER_UNAVAILABLE` while preserving previously accepted evidence; a later retry creates a new run.

Cancellation is fenced immediately in D1 before any external action, and Cloudflare stops issuing Transfer grants or renewing execution authority. It then sends an idempotent cancel command bound to the segment, lease, and fencing identities. A GPU lease is released when the local worker confirms cancellation or when a bounded cancellation grace expires because the worker is unreachable. Lease release does not assert that physical computation has stopped; stale results remain fenced, and the local service's capacity-one rule safely rejects new work until the old execution actually exits.

If Cloudflare assigns a new lease while stale computation still occupies the physical GPU, the local worker rejects the new submission with `GPU_CAPACITY_BUSY`; it neither queues the submission nor creates pending local job state. Cloudflare releases that unstarted lease and restores the same segment waiter at the head of the coordinator queue with its original ordering and unchanged provider-availability deadline. A capacity-busy response cannot renew execution authority.

Every active local execution has a configurable liveness watchdog. Only an Access-authenticated control request that Cloudflare has first verified against the active segment, lease, and fencing token refreshes it. If verified control traffic stops beyond the watchdog grace, the worker cooperatively aborts computation and records the attempt as interrupted. This watchdog limits wasted GPU work and helps physical capacity recover; it neither renews nor replaces the Durable Object lease, and D1 fencing remains authoritative.

The local services restart persistently after host reboot, but local state alone never authorizes computation to resume. Cloudflare must reauthorize recovery through a fresh pull-protocol interaction bound to the current segment, lease, and fencing token. Computation interrupted before artifact finalization resumes as a new execution attempt under the same immutable segment and specification; it may retain the current lease only if Cloudflare confirms that authority is still active, otherwise Cloudflare must acquire a new lease and fencing token. An already finalized `output-ready` attempt remains idempotently reportable with its original descriptor and attempt identity so Cloudflare can decide whether it is still acceptable. The worker never persists Transfer-grant URLs or credentials, and it reuses cached prepared media only after verifying the immutable source checksum.

ADR 0019 remains in force for asynchronous run-level Workflow orchestration, but this decision moves GPU work out of the Cloudflare container. ADR 0020 remains in force for TypeScript orchestration and Python-owned media and computer-vision work, but this decision splits those Python responsibilities between the Cloudflare media container and the local GPU service. ADR 0021 remains in force for a versioned inference-provider boundary, but this decision locates `TrackingProvider` at the trusted TypeScript boundary rather than inside the Python container. ADR 0027 remains in force for actual Python-container egress, including its mediated R2 path. It does not require GPU control to traverse the Python container, does not extend the container's allowed logical hosts, and does not grant general container Internet access.
