# Support offline garage work after initial sync

After a User signs in online, Chassis Notes automatically synchronizes all structured garage records and media metadata and reports Offline ready only when that preparation is complete. Chassis Notes then supports temporary Offline sessions when trackside connectivity is unavailable. Previously synchronized garage data remains available, and every garage and trackside action is retained locally until connectivity returns. Existing media originals become Offline media when viewed or explicitly kept offline rather than being downloaded automatically, while new trackside photos and voice recordings remain safely local until synchronized. Every garage action is retained in durable local state first, regardless of apparent connectivity, and follows the same background synchronization path. Chassis Notes detects an outage automatically, shows a small persistent “Offline—changes will sync later” status, and does not require a manual offline-mode switch. Local work must survive restarts, remain visibly Pending sync rather than appear remotely completed, and resume synchronization automatically when connectivity returns. Append-only and non-overlapping work may merge automatically, but incompatible changes must retain both the local and remote versions as a visible Sync conflict until the User chooses; synchronization never silently applies last-write-wins. Work rejected during synchronization is retained as Needs attention, does not block unrelated queued work, and is never silently discarded. Explicit sign-out removes that User's cached garage and Offline media from the device; if Pending sync work would be deleted, Chassis Notes warns clearly and requires destructive confirmation. Offline support is capability-based rather than tied to named browsers: Offline ready requires Service Worker, IndexedDB, and Cache Storage support. When those capabilities are unavailable, Chassis Notes remains online-only and explains the limitation. Home-screen installation remains optional. Server-dependent processing, including voice transcription and draft extraction, waits for connectivity; passkey administration and uncached external setup imports remain unavailable offline. Browser-hosted AI and long-term disconnected-account access are outside this architecture because durable capture and honest deferred processing satisfy the trackside requirement without adding device-dependent inference or a second authorization lifecycle.

The Car vertical slice establishes the reusable synchronization seam. Create,
edit, archive, and restore commands are stored in the owner-fenced local database
with stable operation and Car identities before the UI reports local success. A
single authenticated operation endpoint stores owner-scoped terminal receipts,
returns exact replays, accepts version zero for edits queued behind local
creation, merges non-overlapping field changes, and retains overlapping changes
as Sync conflicts. Browser connectivity events only wake retry work; successful
or failed requests are the evidence used for availability state. Unavailable
requests schedule bounded retry wake-ups, and a later successful request wakes
queued synchronization immediately without waiting for a browser connectivity
event. The coordinator fences its published view and every asynchronous
completion to the exact owner and session identity, so a sign-out or account
switch hides the previous working copy synchronously and discards stale work.
